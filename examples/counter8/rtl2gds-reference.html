Concepts

What Docker / an image actually is

An image is a frozen blueprint — a saved snapshot of a filesystem, OS, and installed tools, not running yet. A container is a live instance made from that blueprint, the way an object is an instance of a class. Docker's purpose: package a whole working environment so it runs identically on any machine, without the user hand-installing every dependency themselves.

We started this project driving OpenROAD through Docker via its official claude.sh wrapper. It worked for the tool itself, but OpenROAD's published image is amd64‑only — no arm64 build exists — so on Apple Silicon every instruction, including Claude Code's own binary startup, had to run through QEMU CPU emulation. A one-line test prompt burned 20+ minutes of continuous 99.8% CPU before even opening a network connection. That's what pushed the whole project to a native Bazel build instead.

Package managers vs. raw binaries

Not everything "installed" on a system goes through a package manager. Three different mechanisms showed up across this session:

Homebrew (brew)OS-level, language-agnostic. Tracks versions, handles brew uninstall/upgrade. Used for Yosys, Icarus Verilog, groff, pandoc, bazelisk.
npm (global)Language-specific — needs Node already present. claude itself is an npm package; it only looks Homebrew-managed because Node's own install location happens to be under /opt/homebrew.
curl‑script / raw buildNo package manager at all. kimi (Kimi Code CLI) landed via an install script into its own directory. The openroad binary isn't installed by anything — it's a raw Bazel build output sitting in bazel-bin/, untracked by any manager.
Why this mattered here Nothing tracks the openroad binary as an "installed tool" — no brew list, no npm list -g entry. To remove it, you'd delete the folder or run bazel clean. Worth remembering before assuming a package manager can account for everything on the machine.

01RTL authoring

Fable 5 wrote counter8.v directly to spec: an 8-bit up-counter with asynchronous active-low reset and a synchronous enable. No tool invocation — just code.

02Pre-synthesis simulation — Icarus Verilog

A self-checking testbench covering reset hold, enable gating, increment, hold, 255→0 wraparound, and a mid-cycle async reset assert/release.

Caught here A testbench race — reset was released exactly on a clock edge. The RTL itself was correct; the fix was in the testbench.

03Synthesis — Yosys

Mapped to Nangate45 standard cells: synth -flatten → dfflibmap → abc -liberty ... → opt_clean. Result: 24 cells, 63.6 µm² of cell area.

Gotcha check -assert initially flagged count[7:0] as undriven — cosmetic, caused by Yosys not yet knowing Liberty cell pin directions. Fixed by reading the Liberty file before the netlist.

04Formal equivalence — Yosys, SAT-based

Not simulation — a mathematical proof that the synthesized netlist matches the RTL. All 8 $equiv cells proven.

Gotchas Needed -ignore_miss_func (clock-gate cells have no function), async2sync on both sides (SAT can't model async flops directly), and unboxing Liberty whitebox modules so flatten would inline them.

05Floorplan → Place → CTS → Route — OpenROAD

Driven by a Tcl script sourcing OpenROAD's own reference test/flow.tcl, constrained to a 0.6 ns clock. Single pass, no iteration needed. Closed at setup WNS +0.230 ns, hold +0.001 ns, 0 router DRVs, 0 antenna violations.

06GDS merge — KLayout

Combined the routed DEF with the Nangate45 standard-cell GDS shapes into counter8.gds.

Gotcha The KLayout macOS app hangs when run headless, even with quarantine removed. Worked around by installing the klayout pip package into a project-local venv and driving def2stream.py's merge_gds() directly — same engine, no GUI.

07Post-layout gate-level simulation

The routed netlist — now including CTS and hold-fix buffers not present pre-route — re-run against the original testbench, using Liberty-derived behavioral models. Passed.

08Layout render

A PNG snapshot for human inspection, generated via KLayout.

Fix: KLayout blocked by macOS Gatekeeper

Homebrew-installed apps aren't Apple-notarized, so first launch is often refused. This clears the quarantine flag — no sudo needed, since the app is user-owned:

xattr -dr com.apple.quarantine /Applications/KLayout/klayout.app

If macOS still refuses: System Settings → Privacy & Security → find the KLayout block notice → Open Anyway.

Troubleshooting log

Bazel build: no matching manifest for linux/arm64/v8

OpenROAD's official Docker base image is amd64-only. Root cause of abandoning Docker for this project.

Bazel build: no such package 'src/sta'

Cloned without --recursive; three git submodules (src/sta, third-party/abc, third-party/slang-elab) were empty. Fix:

git submodule update --init --recursive

Bazel build: docs/man-page step fails intermittently

Missing pandoc and groff (host requirements for the man-pages Bazel rule, not caught by -bazel-only dependency install). Compounded by a second issue: Bazel's persistent background server caches your PATH at server-start time — installing a tool afterward doesn't help until the server restarts.

brew install pandoc groff
bazelisk shutdown

In the end, the docs/man-pages target wasn't even needed — building just //:openroad instead of //:install skips it entirely.

KLayout hangs headless on macOS

Even klayout -zz -v hangs, quarantine removed or not. Use the klayout pip package instead of the app for any scripted/automated GDS work.

macOS Gatekeeper blocks KLayout.app on first open

See the command reference above — xattr -dr com.apple.quarantine, no sudo required.

Reusable agent

The whole flow above is now encoded as a reusable agent, so the next design doesn't require re-deriving any of this.

WARD/.claude/agents/spec-to-gds.md # subagent definition — toolchain notes, gotchas, required flow order WARD/bin/spec-to-gds # launcher script, added to PATH

Usage

spec-to-gds <design_name> <spec description...>

# example:
spec-to-gds shiftreg8 "8-bit shift register, serial-in parallel-out, sync active-high reset, shift-enable input"

Launches an unattended Fable 5 process (same mechanism proven on counter8: fresh process, --dangerously-skip-permissions, no sandbox) into a new <design_name>_rtl2gds/ directory under WARD, carrying forward every gotcha logged above. Requires a new terminal (or source ~/.zshrc) for the PATH update to take effect.

tail -f <design_name>_rtl2gds/progress.md
tail -f <design_name>_rtl2gds/agent_session.log
